## v0.4.1 — BLE 连接修复与安全加固

### BLE 连接修复
- 扫描重写为宽扫描 + 回调匹配（广播名**或** Tesla Service UUID）——修复部分固件拆分/截断广播名导致"找不到车辆"的问题
- GATT 竞态防护：重新连接前先拆除旧连接；来自过期 GATT 对象的回调被忽略
- 缓存直连超时由 15s 缩短至 6s，快速回退到全量扫描（特斯拉会轮换随机 BLE 地址）
- 配对扫描超时由 10s 延长至 20s，失败提示更明确（先唤醒车辆）
- 所有 BLE 失败记录到应用内诊断日志（设置 → 关于 → 导出日志）

### 安全加固
- Protobuf 解析器边界校验——恶意 BLE 数据不再能导致应用崩溃（DoS）
- 车辆 VCSEC 公钥固定（pinning）——配对时保存车辆公钥，每次握手校验，阻止 BLE 中继/伪装攻击（MITM）
- 禁用应用备份（保护密钥材料）
- GCM nonce/tag 尺寸校验、TLV 值长度校验、Keystore IV 显式随机化

### 说明
- 需与车辆重新配对一次，以启用车辆公钥固定

## v0.3.4 — 修复多语言 ROM（华为/EMUI）语言切换失败

### 已从用户导出的日志确认根因
诊断日志显示真实原因：该华为设备（NOH-AN00，Android 11）系统语言为 `en_CN`——英文语言 + 中国地区码，由设备多语言包设置产生。应用正确应用了 `zh`（`setApplicationLocales applied=zh`，无异常），但 Activity 仍渲染英文，因为仅靠 `createConfigurationContext` 在 EMUI 类 ROM 上不可靠：系统 `en_CN` 语言环境在资源解析中始终优先，导致选中 `values-en`。

### v0.3.4 修复内容
- **`applyOverrideConfiguration` 回退**：每个 Activity 的 `attachBaseContext` 中增加——华为/EMUI ROM 上应用语言的经典、经厂商验证的机制（必须在 `super.attachBaseContext` 之前执行）；与 `createConfigurationContext` 叠加使用
- **显式 `values-zh` 资源目录**：中文成为一等语言资源（APK 语言现为 `--_-- 'en' 'zh'`），不再依赖默认回退，消除多语言环境歧义
- **仅按语言代码应用**（`Locale("zh")`），不受 `en_CN` 等组合标签影响
- **移除语言页等语言守卫**：点击任意语言总是保存 + 重建，点击必有可见反馈
- **运行时语言校验日志**：`AttachBase` 记录每个 Activity 实际解析的语言，新导出的日志可确认回退是否真正生效

### 验证步骤
1. 安装 0.3.4
2. 设置 → 语言 → 点击 English / 中文
3. 设置 → 关于 → 导出诊断日志，检查 `AttachBase` 行：`actualLocale` 应显示与选择一致的 `zh` 或 `en`
4. 若 `actualLocale` 仍显示 `en_CN` 派生值，请分享日志——导出机制已就位，用于定位剩余层级

## v0.3.2 补丁版本

### 修复：语言选择现在每次点击都有响应
上一版本静默丢弃点击，因为点击处理依赖表单填充标志（`isFormPopulated`），该标志仅在 DataStore 流发出后才设置；若该发出延迟或失败，所有点击均被忽略——与"选择任意语言无反应"的报告吻合。重建后流程不再受此影响：

- 点击处理不再依赖表单填充标志；改用内存语言缓存比对，点击总是生效
- 语言缓存改为静态字段，在每个 Activity 的 `attachBaseContext` 直接读取（无 Hilt 注入时序依赖，任何顺序均可）
- 单选按钮改为直接点击监听，而非 RadioGroup 回调（不受程序化 `check()` 干扰）
- 切换失败通过可见 Toast + logcat（`LangDebug` 标签）提示，不再静默失败
- 每一步添加诊断日志（`LangDebug`），若仍有问题可快速定位

### 若仍失败请协助
安装本 APK 复现问题后运行：
```
adb logcat -s LangDebug
```
并分享输出。

## v0.3.1 补丁版本（已废弃）

> 已废弃：仍无法在目标设备生效，由 v0.3.2 取代。

### 修复：应用内语言切换现在可靠工作
根因：过度依赖 `AppCompatDelegate.setApplicationLocales` 的隐式 Activity 重建（应用使用 Material3 主题，语言监听器中的任何异常都会静默中断整个链路）。以可靠机制重建：

- `LanguageManager` 维护内存语言缓存，`setLanguage()` 同步持久化 + 应用 + 更新缓存
- 每个 Activity 在 `attachBaseContext` 通过 `createConfigurationContext` 应用语言（不依赖主题/库行为）
- 切换语言触发当前页面显式 `recreate()`；冷启动首帧前也应用已存语言
- 语言监听器异常安全（不会再次静默死亡）

- `values-en` 资源确认打包（aapt: locales 'en'）
